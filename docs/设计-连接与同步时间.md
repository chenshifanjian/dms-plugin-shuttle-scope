# 设计：在面板里改 SMB 连接与同步时间

现状：连哪个 NAS、用哪个账号、多久同步一次，只能手改 `~/.config/shuttle/config.toml`，改完还得重启服务。
本次把这两件事搬进面板的第三个视图（`同步范围` / `云端差异` / `连接`），并且明确一条硬边界：**密码永远不落磁盘文件**。

## 1. 配置模型与写入位置

Shuttle 的配置分三段，改连接只动前两段：

```toml
[shares.zspace]
host  = "192.168.1.10"
share = "团队文件-项目文档"
user  = "账号"            # 只有账号，没有密码

[profiles.live]
triggers      = ["realtime", "share-available"]
poll_interval = "60s"
interval      = "6h"      # 可选
at            = ["02:00"] # 可选

[shuttles.moren]
local  = "~/Documents/smb"
remote = "zspace:."
```

- 密码：`secret-tool store service shuttle username <完整 SMB URL>`，**条目 key 是完整 URL**，不是账号名。
  所以改地址或账号后旧条目失效，`share set` 必须 `clear` 旧 URL 再 `store` 新 URL。
- `config.toml` 里永远只出现 host / share / user 三个字段。

## 2. 密码怎么从输入框走到 keyring

```
DankTextField(echoMode: Password)
  → QML 属性 connPwInput
  → connProc.environment = { SHUTTLE_SCOPE_PW: pw }   // 进程环境，不写文件
  → shuttle-scope share set --password-env SHUTTLE_SCOPE_PW
  → Python 读 os.environ，随即 pop 掉该变量
  → subprocess.run(["secret-tool","store",...], input=password)   // 走 stdin
```

三条约束逐条对应踩过的坑：

1. **不进 argv**：密码一旦进 `argv`，`ps`、`/proc/<pid>/cmdline`、shell history 全能看到。所以只传变量名，不传值。
2. **不带尾换行**：实测 `printf 'abc123\n' | secret-tool store` 存进去是 `abc123\n`（`xxd` 末尾 `0a`），SMB 认证必失败。Python 侧 `input=password`（不加 `\n`）。
3. **用完即抹**：QML 里 `root.connPwInput = ""` 在发命令前就清；Python 读完 `os.environ.pop`；进程退出环境随之消失。

## 3. 改连接：先测连，连不上就不改

`share set` 的顺序是刻意的：

1. 解析地址（宽容写法，见下）→ 拿到 host / port / share / user / 子路径。
2. 取密码：`--password-env` 给了就用它；没给就从 keyring 按**新 URL**取（留空＝沿用已存的）。
3. `smbclient` 真连一次，`ls` 一下该共享（默认超时 20s）。
   **连不通直接退出，一个字节都不写**——避免把能用的配置换成连不上的。
4. 通过才写配置：`clear` 旧 URL 条目 → `store` 新条目 → 定点改写 TOML。
5. `shuttle status` 复核新配置被 daemon 接受（看 `config reloaded`）；不接受就用备份回滚。

地址解析接受这几种写法，都归一成 `(host, share, sub)`：

| 写法 | 结果 |
| --- | --- |
| `smb://10.0.0.2/团队文件` | 10.0.0.2 / 团队文件 / "" |
| `//10.0.0.2/团队文件` | 同上 |
| `\\10.0.0.2\团队文件` | 同上 |
| `10.0.0.2/团队文件` | 同上 |
| `smb://bob@nas:4458/团队文件/前进的项目` | nas:4458 / 团队文件 / 前进的项目（user=bob） |

拒绝：空串、只有主机没有共享名、地址里写密码（`smb://user:pw@host/share` 直接报错，防止密码被抄进配置）。

## 4. 同步时间：四个键的语义

| 键 | 含义 | 空值 |
| --- | --- | --- |
| `triggers` | 谁触发同步：`realtime`（共享有变动就传）、`schedule`（到点整体比对）、`share-available`（NAS 刚连上补一次） | `[]` = 只有点「立即同步」才跑 |
| `poll_interval` | `realtime` 下多久查一次共享有没有变化 | 空 = 删除 |
| `interval` | 定时同步的间隔，`30m` / `6h` / `1d` | 空 = 删除 |
| `at` | 每天固定时间点，可多个，`["02:00","14:30"]` | `[]` = 删除 |

`interval` 与 `at` 同时存在时两个都生效（每隔也跑、到点也跑）。面板上四个预设就是这四组的快捷写法：

- 「每天 02:00」→ `triggers=[realtime,schedule]`, `at=["02:00"]`, `interval` 清空
- 「每 6 小时」→ `triggers=[realtime,schedule]`, `interval="6h"`, `at` 清空
- 「每 12 小时」→ 同上，`12h`
- 「只手动」→ `triggers=[]`，`interval`/`at` 都清空

改完 Shuttle 自己会 `config reloaded`，不需要重启服务（实测 `started=1 disabled=0 removed=0`）。

## 5. 幂等保存：值没变就别动文件

`set_key` 只替换值、保留 `key` 与 `=` 之间的对齐空格。后来又加了一条：**如果这一行现在的值和新值一模一样，整行原样返回**。

原因是上一版在面板里点一次「保存并测试」，就把配置里的行尾注释全抹掉了：

```diff
- share = "团队文件-项目文档"            # 共享名，不是 共享文件 里的子目录
+ share = "团队文件-项目文档"
```

现在配合 `_write_conf` 的「`text == raw` 就完全不落盘、也不备份」，重复保存是字节级 no-op（实测 `diff` 无输出）。备份只保留最近 20 份。

## 6. 面板结构

第三个按钮 `连接`，视图内两段：

```
[当前连接卡片]  host / share、账号 · 密码状态、本机目录
[SMB 地址] [账号] [密码（留空＝不改）]  → 保存并测试 + 结果行
[本机目录（同步落地的文件夹）] [保存]   → 结果行（有 warning 才显示）
[同步时间 (profile: live)] 一句话摘要 · 下次时间
[实时] [定时] [上线补跑]            三个开关
[每天 02:00] [每 6 小时] [每 12 小时] [只手动]    预设
[每隔] [每天几点]  [实时检查共享的间隔]  → 保存同步时间 + 结果行
```

### 弹窗高度：内容量高 + 手动拖拽（v0.5.0 起）

不再写死 `popoutHeight`（v0.4.0 的 2050 是量出来的固定值，内容一变就太长或被裁）。现在两条来源，优先级从高到低：

| 来源 | 属性 | 生效条件 | 存哪 |
|---|---|---|---|
| 用户拖拽 | `manualPanelH` | `> 0` 就用它 | `savePluginState("shuttleScope","panelHeight",h)` → `~/.local/state/DankMaterialShell/plugins/shuttleScope_state.json` |
| 内容量高 | `autoPanelH` | 没拖过（`=0`）时用它 | 不存盘，每次内容变化重算 |
| 兜底 | 700 | 首帧还没量出内容 | — |

`autoPanelH` 在 `DankFlickable` 内部算：

```qml
readonly property real wantH: (col.childrenRect.height > 0)
    ? Math.min(col.childrenRect.height, root.maxPanelH - chromeH) + chromeH : 0
onWantHChanged: {
    var v = Math.max(340, Math.round(wantH / 2) * 2)
    if (wantH > 0 && Math.abs(v - root.autoPanelH) > 3) root.autoPanelH = v
}
```

- `col.childrenRect.height`：`ColumnLayout` 放进 `DankFlickable` 后 `implicitHeight` 恒为 **0**，只能读 `childrenRect`（v0.4.0 踩过的坑：内容超出既不滚动也不报错，静默裁掉底部）。
- `+ chromeH`：`flick.height = popoutHeight - headerHeight - detailsHeight`，内容高要补上标题栏/底栏才等于 `popoutHeight`。
- `Math.min(…, maxPanelH - chromeH)`：`maxPanelH` 由 `parentScreen` 限到屏幕高，再长的列表也不会把面板顶出屏幕（超出的部分在面板内滚动）。
- 偶数对齐 + 差 3px 内不更新：防抖，避免绑定来回抖。
- 拖动途中不写盘（`setPanelH(h, false)`），松手才存（`onReleased`）；**双击底边手柄**归零，回到自动高度。
- `同步时间` 默认收起（`schedOpen=false`），收起时面板约 **856 css 高**（实测），展开后随内容长高，不再是固定 2050。

历史教训留在这里：旧版本靠临时打一行 `DBG ph=<popoutHeight> flick=<popFlick.height> content=<col.childrenRect.height>` 量高度，实测 `content=1923 / header=40 / details=40` 才定 2050。以后**新增控件不要再手动调 `popoutHeight`**，让它自己量。

## 6.5 本机目录（`local set`）

`[shuttles.<name>].local` 决定「同步落到哪个文件夹」，跟「连哪台 NAS」是两件事，所以它跟地址/账号/密码并列放在连接视图里（同一行：输入框 + `保存` 按钮）。

| 规则 | 行为 |
|---|---|
| 写法 | `expanduser` + `realpath`，接受 `~/Documents/smb`、相对路径（先转绝对）、尾部斜杠 |
| 拒绝 | 空、根目录 `/`、家目录 `$HOME`、指向已存在文件的路径 |
| 幂等 | 与当前值相同 → `changed:false`，**不写盘、不建备份**（`realpath` 后比较，所以 `~` 与绝对路径视为相同） |
| 不存在 | 自动 `mkdir -p`，返回 `created:true` |
| 空目录 | 返回 `warning`：「新目录是空的，保存后 shuttle 会把 NAS 上的文件整批下载到这里（云端索引里有 N 个文件）」，N 取 `~/.cache/shuttle-scope/remote.json` 的 `count`（只读缓存，不联网） |
| 上下级 | 新目录是旧目录的上级 / 旧目录在新目录里 → 拒绝；新目录在旧目录里面（嵌套同步）→ 拒绝；确认要这么做加 `--force` |
| 复核 | 写盘前用 `tomllib` 重解析，`local` 值不一致就不写 |

密码通道与 `share set` 完全无关：`local set` 不碰 keyring，也不需要测连。

## 7. 已知限制

- `share set` 只改 `[shares.*]` 的第一条（本项目只有一个共享），多共享场景未做选择器。
- 改 `local` 已做（`local set`，见下节），但**换目录不搬文件**：旧目录里的文件留在原地，新目录是空的就整批从云端下载，这是设计上的取舍不是 bug。
- 测连只验证「能列目录」，不验证写权限；真写失败要靠 `shuttle status` 的报错。
- 面板里没有「删除共享」入口，只有改。
