# 设计：云端 ⇄ 本地差异视图

## 要回答的问题

用户的原话：

> 比如我代上传里的文件删了「但是设置代上传这个文件夹不同步了」，然后我点开扩展，我能看到这个文件没存在我本地，但是云端存着呢

也就是说：**同步范围排除掉的目录，本机删了不会传播到 NAS，NAS 上的副本会一直躺着。** 这类「幽灵文件」在 Shuttle 自己的状态里完全看不见（它只报参与同步的那 26.7 GB），必须单独去问 NAS。

## 为什么是 SMB 直连，而不是复用 Shuttle

Shuttle 的 `sync` 是增量的，它知道自己要不要传某个文件，但不保存一份「云端完整清单」给外部查。要拿云端真相只有两条路：

1. 让 Shuttle 输出它的索引 —— 没有稳定接口，且被排除的路径根本不进索引。
2. 自己读 NAS —— 选这条。

`smbclient -c 'recurse ON; prompt OFF; ls'` 一次能列完整共享树。实测 `待分类`（3,726 个文件）2.9 秒，**全共享 8,677 个文件约 14 秒**。这个量级决定了架构：

- **不能每次开面板都扫**：14 秒的 I/O 不能挂在 UI 线程上。
- **缓存整个共享**，而不是只缓存当前层：一次全扫之后，任何子目录的比对都是本地字典操作（毫秒级）。所以面板里逐层下钻、来回切目录都不再碰网络。

缓存落在 `~/.cache/shuttle-scope/remote.json`：

```json
{"at": <epoch>, "files": {"相对路径": 字节}, "dirs": ["相对路径", ...],
 "stale": false, "warning": "", "fresh_seconds": 13.8}
```

`TTL = 600s`。过期后 `diff` 仍用旧缓存，但把 `stale` 标出来，面板显示「云端清单 N 分钟前更新」；只有用户点「重扫云端」(`--refresh`) 才真正重列。

## 凭证

密码只在系统 keyring（`service=shuttle`，`username=<完整 SMB URL>`）。`remote.py` 用 `secret-tool lookup` 取出来，写进一个 `chmod 600` 的临时 auth 文件，`smbclient -A` 读它，用完立即删。`config.toml`、日志、本文件、知识库都不出现口令。

## 比对语义

只比 **文件名 + 大小**：

| 状态 | 含义 | 用户看到 |
|---|---|---|
| `remote_only` | 云端有、本地没有 | 「仅云端 · 10.3 GB」 |
| `local_only` | 本地有、云端没有 | 「仅本地 · …」 |
| `differ` | 同名但大小不同 | 「大小不同 · 本地 X / 云端 Y」 |
| `same` | 同名同大小 | 「一致 · …」 |

不比内容哈希：读 100 GB 级的 SMB 内容不可接受。不比 mtime：SMB 时间戳跨时区、夏令时都不可靠，会造出海量假差异。

`is_meta_path()` 对**任一路径段**匹配 Shuttle 的 `ignore` 模式（`~$*`、`*.tmp`、`Thumbs.db`）和元数据名（`.shuttle-versions`、`.stfolder`、`.stversions`、`.DS_Store`、`.stignore`）就跳过。第一版漏了 `.shuttle-versions`，结果每个目录都凭空多出「云端独有」的文件，已修。

## 聚合与排序

用户在 `待分类` 一层就要看出「哪个目录云端多东西」，所以目录行不显示自己，而显示**整棵子树**的聚合：

```json
{"name":"代下载","dir":true,"remote_only":3700,"remote_only_bytes":71627612864,
 "same":21,"files":0,"in_local":true,"in_remote":true,"diff_count":3700}
```

排序：目录优先 → `diff_count` 降序 → 名称 `casefold()`。`same` 的文件排在后面，避免把差异淹掉。

实测 `待分类` 一层：

- `代下载` 云端多 3,700 个 · 71.6 GB（本机只剩 21 个）
- `代上传` 云端多 2 个 · 26.6 GB
- 其余 `.3mf` 文件全部一致

## 与「同步范围」共用一个弹窗

不新开窗口、不做网页（用户明确否掉网页方案）。弹窗顶部加两个按钮：

- `同步范围`（原有视图，带复选框）
- `云端差异`（只读，复选框位换成「仅云端 / 仅本地 / 不同」和目录的差异计数）

两个视图共享同一套「返回 + 当前路径」导航和同一份 `curPath`，所以看到 `代上传` 云端多两个文件后，切回「同步范围」还是同一个位置，可以直接点复选框决定要不要重新纳入同步。

差异视图**只读**，避免「看差异」和「改同步范围」两个动作混在一个点击里。

## 踩过的坑

1. **`Proc.runCommand` 有默认超时**。第一次实现里「打开面板就 `--refresh`」，结果卡片显示「读取失败（exit 124）」——14 秒的全扫撞上了 DMS 内部的超时。改成：打开只读缓存（`--quick`），重扫显式传 `timeoutMs = 180000`。
2. **`excluded_by` 一直是空串**。原来用 `ancestor_hit()`（只认严格祖先），而 `代上传` 命中的恰恰是它自己那条 `exclude`。改成自己比一遍：`rel == q or rel.startswith(q + "/")`。
3. **QML 预览没法靠 `PanelWindow`**。`PanelWindow` 塞进 `PluginComponent` 不实例化，改成一过性 `Timer` 调 `triggerPopout()`；而且 DMS 冷启动要 8~10 秒，定时器不能太早，否则 pill 还没挂到 bar 上、`positionPopout()` 返回 false，窗口根本不开。

## 后续可以做的

- 从差异行直接「恢复同步」（把该路径从 `exclude` 移除）或「只删云端」（需要 Shuttle 侧能力，暂不做）。
- 后台定时重扫（例如每小时一次），让卡片常年接近真实。
- 差异结果落盘，面板打开时先显示上次结果再刷新。
